\section{Introduction}
\input{generated/intro_finding.tex}

TOOLDEC already enforces tool syntax without fine-tuning~\cite{tooldec}. Prior work separates structural and content failures and tests grammar mitigation in quantized models. We ask whether strict enforcement changes the \emph{incremental precision gap} differently from permissive or trigger-gated grammars. A quantized model can gain simply because an intervention helps every precision. A grammar admitting arbitrary text cannot guarantee schema-valid output. We therefore use matched full-precision controls and check what each decoder admits.

The benchmark is single-turn prediction; no generated call is executed. The separate sensitivity is not pooled into the primary matrix or interpreted as a parser-only causal experiment~\cite{metaprompt}.

\section{Related work}
Quantization studies show dependence on recipe and workload~\cite{bf16}. Aggregate agent success can obscure process failures~\cite{flat}; decision-level analyses already study which tool-use decisions low-bit weights disrupt~\cite{wu}. These motivate a precision interaction, beyond the general observation that compressed models can make tool errors.

The closest software reports, QuantCall, QuantMCP and Toolhound~\cite{quantcall,quantmcp,toolhound}, differ in engine, precision controls, tasks and replication. QuantCall's default grammar unions a schema-shaped call with unrestricted text. QuantMCP describes a related escape and a forced-envelope probe with stalling. Toolhound reports trigger-gated comparisons on MLX and a custom suite. These substantive prior experiments motivate the mechanisms and confirmation criteria in Table~\ref{tab:replication}.

StructureBench and Chavan study small-model structural validity and content accuracy~\cite{structure,chavan}. Repair, Not Improvement isolates stopping and tool-name restrictions in routing, using repeated runs and paired inference~\cite{repair}. JSONSchemaBench studies schema coverage and efficiency~\cite{schema}. Constraint Tax shows that final-response grammars can exclude a serving protocol's tool calls~\cite{constrainttax}. We therefore constrain the declared call envelope and distinguish configuration, initiation, completion and correctness. Serving-stack differences can independently change apparent tool fidelity~\cite{serving}. Our conceptual replication retests mechanisms without reproducing another engine or live MCP execution.\input{replication_table.tex}

\section{Experimental design}
\input{method_overview.tex}
\subsection{Frozen tasks, models and precision}
\input{generated/setup.tex}
All conditions share original items and accepted answers, selected without model predictions. The pilot calibrates runtime and cost. Prompts are frozen from pinned publisher templates with a fixed Llama template date.

Weights are exported once to F16 GGUF and the quantized artifact is generated directly from that export. The checkpoint's storage dtype may differ from the F16 reference. Both K and V caches stay F16. Qwen thinking is disabled~\cite{qwencard}. Model revisions, source and output hashes, conversion commands, server arguments and the pinned llama.cpp source~\cite{llamacpp} are recorded. Each model uses one A10 worker for all arms and precisions, with a fixed Modal allocation selector. Records retain device-reported A10/A10G labels and drivers; model sessions may use different physical hosts.

\subsection{Decoder languages and prompt contract}
Each model's arms share rendered prompts and offered tools. The primary Llama prompts use the single-object JSON tool branch of \texttt{tokenizer\_config.json}'s embedded HF chat template, with \texttt{tools\_in\_user\_message=True}. Both revisions share the template hash in Appendix~\ref{app:settings}. We added a system-message JSON-array convention for parallel calls, but the HF template's later user-message instruction requests one JSON object. These instructions conflict on parallel tasks. Meta documents Pythonic call lists~\cite{metaprompt}, which the primary JSON contract does not evaluate. Llama findings concern this declared contract, not its best supported interface. Qwen uses tagged call objects with \texttt{name} and \texttt{arguments}; Llama uses objects with \texttt{name} and \texttt{parameters}, or arrays for parallel calls. All arms use \texttt{NO\_CALL} when no offered tool applies. The grammar never uses the expected function, accepted values or gold call count.

\textbf{Free} applies no grammar. \textbf{Loose} unions the schema-shaped language with arbitrary text, reproducing the escape as a control. \textbf{Trigger-strict} leaves initiation unconstrained and activates the call language at the declared prefix. Qwen uses its preserved call token; Llama uses one pattern matching the earliest object or array opener, including an opener merged into a token. \textbf{Whole strict} admits only a documented call sequence or the explicit no-call form. Parallel-call count and order are not fixed to the reference. Lazy activation can encounter a merged trigger-containing token whose remainder violates the call language. Known replay errors are retained as failed attempts, rather than retried or admitted through a grammar escape.

The compiler allows documented object keys in any order, requires specified keys and forbids duplicates. As an explicit API policy, known property sets are closed; free-form dictionaries stay free-form. For nested BFCL dictionaries with untyped required fields, names are retained but values are unconstrained; answers never supply types. These normalization choices are released as part of the intervention.

Finite character-level membership checks test selected schemas, malformed strings, unknown functions, missing or extra arguments, types, key order, parallel calls and abstention. These show tested coverage, without proving every JSON Schema feature or token-level behavior. Before collection, synthetic runtime probes force a known trigger to verify literal replay and the server's configured lazy mode. These are setup checks, not benchmark successes. No engine patch is used.

\subsection{Execution and scoring}
Decoding uses temperature zero and shuffled requests, with seed and schedule labels frozen before execution. Identical greedy outputs remain operational repeats, not independent items. Context and output limits, slots, cache settings and stop strings match across arms. Grammar acceptance itself changes when termination is legal. Llama uses publisher token IDs to avoid duplicating the template's beginning-of-text marker. An earlier collection with that duplication remains an aborted setup attempt, stopped before accuracy inspection. Qwen prompts remain strings, using publisher settings that disable an added beginning-of-text token. Logs retain cache-reuse timings and actual generation settings. The cloud supervisor checkpoints events and enforces queue, runtime and scheduling limits frozen before execution. The researcher permitted concurrent full studies after separate pilots; these runs do not establish isolated cross-model throughput.

Official BFCL AST matching determines correctness~\cite{bfcl}. We parse the declared JSON envelope into calls without executing them. The pinned checker is unmodified; a minimal registry entry supplies its name-normalization flag without importing unrelated API clients. The unchanged official irrelevance helper uses the same parsing adapter. Irrelevance can credit outputs with no parsed call even when our format diagnostic rejects their prose; we report these separately. Required-call accuracy is the primary endpoint.

Our deterministic diagnostics retain multiple flags and an ordered primary label: format failure, wrong or hallucinated function, missing/extra or hallucinated arguments, wrong type and wrong value, plus missing/extra calls and operational statuses. A schema-valid parallel mismatch is not labeled a known value error without evidence from the checker. Incomplete output and runtime failures remain visible. Unstarted budget-censored cells are reported as incomplete, rather than filled with synthetic predictions.

\subsection{Estimands and paired uncertainty}
Let $A_{p,d}$ be official item accuracy at precision $p$ and decoder $d$, with $f$ denoting free decoding. For the quantized precision $q$, define
\begin{align}
 L_f &= A_{\mathrm{F16},f}-A_{q,f},\\
 L_d &= A_{\mathrm{F16},d}-A_{q,d},\\
 R_d &= L_f-L_d.
\end{align}
$R_d$ removes the decoder effect already present at F16. We also compare $R_{\mathrm{whole}}-R_{\mathrm{loose}}$ and the corresponding trigger contrast on paired observations. These are intervention effects, not an identified fraction of purely syntactic knowledge loss: schemas restrict names, keys and types, and can redirect subsequent value choices.

Primary percentile intervals use crossed paired resampling of original item IDs and operational-run labels, sharing draws across all conditions and models. Item-only intervals provide a sensitivity check. Category rates use their original item subsets. Intervals are pointwise and unadjusted for multiple comparisons; exploratory contrasts are labeled. Without observed failures, empirical bootstrap intervals can degenerate and cannot bound rare unobserved population failures. The recovery share $R_d/L_f$ is undefined for nonpositive observed free loss. We withhold its interval when bootstrap denominators are unstable and never clip values into a partition.

\section{Cost, limitations and practical implications}
\input{generated/cost.tex}
Forecasts are assumptions. Timings omit unmeasured platform stages; metering can lag and cannot establish storage completeness. Earlier failures remain released.

The frozen BFCL sample is not a complete leaderboard evaluation. AST correctness establishes neither safe execution, successful multi-turn agents nor correctness on unseen APIs. The irrelevance sample is small. Fixed inference, cache dtype, weight recipe, envelope and schema normalization limit generalization to other quantizers, KV-cache compression, larger catalogs or engines. Prefix triggering is an operational rule, not a direct measure of internal intent; log-derived activation is not a direct sampler-state trace.

\input{generated/failure_sensitivity.tex}

Closed schemas can forbid useful undocumented arguments; typed values can still be wrong. Parser policy affects prose, abstention and parallel-call scoring. Operational repeats cover neither new training runs, quantization builds or templates nor generalization across hardware. Intervals crossing zero do not prove equality.

Operators need task accuracy under the same serving contract and a matched high-precision control. Structural guarantees remain useful without accuracy gains. The planned follow-up compares schema-audit and precision-fallback methods with ordinary retries; these methods are not evaluated here.

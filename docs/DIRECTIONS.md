### What changes the direction choice

The positive and negative reports are **not yet a demonstrated contradiction under identical conditions**: they change models, tasks, engines, representations, grammar activation, and metrics. A useful replication explains that apparent disagreement by crossing those interventions, rather than declaring one report false.

An unrestricted-text grammar branch is not an abstention-safe validity guarantee. Conversely, forcing a call is not a fair solution to abstention. A valid experiment must offer a finite, explicit no-call representation and permit legitimate multi-call outputs. Structurally valid but incomplete generations must still fail the completion endpoint.

Other primary-source checks also limit novelty claims: [Self-Refine](https://arxiv.org/abs/2303.17651v2) already studies self-feedback; [FrugalGPT](https://arxiv.org/abs/2305.05176) already studies cascades. A recent [confidence study](https://aclanthology.org/2026.uncertainlp-main.26/) distinguishes pre-mask and post-mask uncertainty. [Xyntetik's vendor evidence](https://xyntetik.com/evidence/) already reports constrained call shape surviving quantization while argument agreement deteriorates; agreement with Q8 is not correctness against a task reference. None makes our controlled follow-up pointless, but generic retry, cascading, or “valid JSON can be wrong” is not a new algorithm or finding.

## 3. Concrete directions

### Direction 1 — Does strict enforcement recover a quantization gap that permissive grammars fail to recover?

**Question.** With the same model, task, prompt, and limits, how does the incremental FP16→Q4 tool-call loss change under permissive, trigger-gated, and whole-response strict constraints? Is an apparent null caused by unenforced structure, incorrect content, or incomplete generation?

**Gap and contribution.** G1–G3 do not supply a shared intervention comparison. G4–G5 do not establish its quantization interaction. G11 shows that stop behavior must be controlled. The contribution would be an auditable factorial replication and a grammar conformance harness, not the first observation of structural/semantic differences. Use source-faithful probe cases to anchor the reports, then a common benchmark to compare interventions.

**Minimal experiment, proposed scope.** Three small anchor models: Qwen3-0.6B (QuantCall), Llama-3.2-1B (QuantMCP), and Llama-3.2-3B (Toolhound); FP16 and Q4_K_M from the same source checkpoints. This **proposes adding two anchor models and reducing the precision grid** relative to the original plan; it requires the researcher's choice and license/access verification. It is not an implemented substitution.

Freeze **200 BFCL cases**: 60 simple, 60 multiple, 60 parallel, and 20 irrelevance diagnostics. Report required-call accuracy separately; the small irrelevance set is a diagnostic, not a precise abstention benchmark. Four decoder arms:

1. **Free:** no mask.
2. **Loose:** schema-shaped calls unioned with arbitrary text, reproducing the escape behavior as an intervention.
3. **Trigger-strict:** native call initiation remains free; the call body becomes schema-constrained after initiation.
4. **Whole-response strict:** completed responses must be a documented call sequence or a finite explicit no-call form, with no arbitrary-text escape.

Use each model's chosen native envelope consistently **within model**; do not impose a common unnatural wrapper across model families. For a given model, all four arms see the same rendered prompt explaining the full output contract. Match stop rules, token caps, tool ordering, and context limits. The loose/trigger arms are **mechanism-matched reproductions**, not a claim to reproduce another engine bit for bit. Maintain a small, separately labelled source-faithful probe using the original prompt/envelope where available; a frozen MCP prompt probe cannot reproduce live MCP task success.

Run **five registered run seeds/schedules** per cell, retaining the same items: **3 × 2 × 4 × 5 × 200 = 24,000 generations**, plus the unchanged pilot. At temperature zero these are operational repeats: vary registered request order/scheduling and record output stability, without calling duplicate greedy outputs independent samples. Pair item/run draws across arms. Five runs characterize some runtime variation; they do not guarantee power for a small effect. No tuning on the test set and no filtering for FP16 success.

Primary endpoint: official BFCL AST accuracy difference-in-differences on required-call cases, subtracting the decoder effect already present at FP16. Use BFCL's official relevance/irrelevance evaluation path for the separate no-call diagnostics. Also report item transitions, independent schema validity, complete-call rate, wrong-tool/value rates, whitespace loops, token-limit terminations, and attempted-case denominators. A finite call/no-call grammar must support optional fields and parallel calls without encoding gold call counts. Validate the grammar offline against generated valid/invalid strings, then check observed outputs; testing cannot prove coverage of every JSON Schema feature. Confirm the trigger interface and its reached constraint mode on the pinned official llama.cpp build before paid work; a required engine patch would change the feasibility assessment and must not be hidden.

**Cost/time.** Conditional $7.63–$11.71, 6–10 total L4 hours plus the stated reserve. Budget is tight if full-generation throughput is slow; the pilot must project every cell before approval of the full run. Offline grammar checks and data freezing come first.

**Negative outcome.** All matched gaps could be near zero; strict enforcement could only exchange parse failures for wrong values, or increase truncation. The initial “contradiction” might disappear entirely after controlling representation and scoring. Wide paired intervals would mean inconclusive recovery, not proof of no effect. That still produces a useful replication, with correspondingly modest publication claims.

### Direction 2 — Can a cheap schema audit choose when precision escalation is worth paying for?

**Question.** Can a quantized model's schema-aware recheck identify bad *schema-valid* calls well enough that selectively rerunning the original request in FP16 improves accuracy per GPU-second over strict decoding, ordinary retries, or arbitrary fallback?

**Gap and contribution.** G8 measures retries following observable environment failures; it does not supply a gold-free detector for wrong but valid arguments. G3's attribution is diagnostic, not a deployed escalation policy. G6 explicitly limits the behavioral usefulness of its margin forecast. Cascading and self-refinement already exist; the proposed contribution is a held-out test of this particular quantization-aware policy and its cost/accuracy trade-off, not a new generic cascade.

**Minimal experiment.** Use the originally requested Qwen2.5-1.5B and Llama-3.2-3B, FP16 and Q4_K_M, fixed FP16 cache, strict schema decoding. Freeze 400 cases with a tool-disjoint **80-development / 320-test** split where possible; otherwise disclose family overlap rather than claim it absent. Use three operational run seeds. At both precisions collect three outputs per case:

- Original one-pass call.
- One generic “check and correct this call” retry.
- One schema-aware audit: re-read the original request and offered signatures, check chosen function, required information, units/enums, and argument values, then return a complete confirmed/corrected call.

The audit gets **no reference answer, AST verdict, hidden environment error, or FP16 output**. Its constraint comes from the offered schemas only. Keep both retry budgets matched. The gate is simple and frozen: escalate if the original and audit disagree on the canonical function/arguments, or if an observable validation/completion failure occurs. If they agree, retain the original. A wrong agreed answer stays wrong; disagreement is not proof of error. For parallel calls, canonicalization must respect the official order/multiplicity semantics.

This is **2 models × 2 precisions × 3 outputs × 3 runs × 400 = 14,400 generations**, before the pilot. FP16 original-request outputs can be reused offline to evaluate fallback because escalation reruns that identical original request, not an error-enriched prompt. Report both actual collection spend and the simulated deployed-policy cost; an offline replay must still charge every audit, escalated call, load, and switching overhead to the policy. Confirm one small online batch before claiming deployed latency or savings.

**Required competitors.** Q4 strict-only; one validation-triggered retry using available errors; one generic self-refinement; unconditional schema-aware correction; always-FP16; and random FP16 fallback at the same measured expected compute budget, including the audit cost. Jang-inspired validation retry is an adapted baseline, not an exact reproduction of its three-attempt simulator loop. Compare ordinary retry with the audit to test whether schema awareness adds anything. Publish correct→wrong revisions, false escalation, missed bad calls, and accuracy/GPU-second frontiers. Count validity and semantic correctness separately.

Do not choose a fallback fraction or revise the audit prompt on the test set. An optional pre-mask margin gate is a later ablation only if raw logits are reliably accessible; [post-mask confidence can measure a different quantity](https://aclanthology.org/2026.uncertainlp-main.26/). No engine modification is needed for the proposed disagreement gate.

**Cost/time.** Conditional $9.67–$13.76, 8–12 total L4 hours plus reserve, including development and online confirmation. The upper end leaves little room for failures. If measured cost cannot fund the matched controls, stop and revise the proposed design with the researcher rather than quietly omit competitors.

**Negative outcome.** Audit and original could agree on the same errors, refinement could damage correct calls, FP16 could share the semantic mistakes, or random fallback could dominate after audit cost. If generic retry ties the proposed audit, prefer the simpler baseline. A null is evidence against this gate, not evidence that all escalation policies fail.

### Direction 3 — Can information-preserving schema rendering reduce semantic damage without more inference?

**Question.** Does placing function signatures and required arguments before descriptive prose help quantized callers more than full precision, while keeping the catalog, meanings, and decoder fixed?

**Gap and contribution.** G7 changes tool selection and context settings; G3's PA-Tool comparison changes names. Neither establishes this exact rendering-only precision interaction. This is modest novelty: a reproducible practical prompt intervention, not a new retrieval method or a claim that shorter prompts always help.

**Minimal experiment.** Original Qwen2.5-1.5B and Llama-3.2-3B; FP16/Q4_K_M; 400 frozen required-call BFCL items; three run seeds; three renderings: original documentation, compact/minified serialization retaining all information, and signature-first layout retaining the **same names, descriptions, parameter constraints, examples, and tool order**. The original tool schema still generates the identical strict decoder in all arms. Do not delete semantic qualifications or silently rewrite examples with an LLM.

This gives **2 × 2 × 3 × 3 × 400 = 14,400 generations**, plus pilot. Original and compact layout separate basic serialization savings from the proposed signature-first placement. Record token counts and prefill time; use a token-matched whitespace/padding ablation on a small frozen subset only if budget permits, and acknowledge padding is an imperfect causal control. The main conclusion concerns the full rendering intervention, not a pure token-count mechanism. Score with official AST, paired precision × rendering CIs, and a “helped Q4 but harmed FP16” audit. Verify preservation of structured fields and manually review the fixed renderer before test inference.

**Cost/time.** Conditional $5.59–$9.67, 4–8 L4 hours plus reserve. No extra model pass or retrieval model at deployment; code and documentation are straightforward. This has the lowest implementation risk after the replication.

**Negative outcome.** Reordering can hurt pretrained format expectations; minification alone can explain all gains; the precision interaction can be indistinguishable from zero. Then the result supports leaving publisher-native rendering alone. Do not claim a universally better schema format from one favorable family.

### Direction 4 — Which exact-value errors from cache quantization survive strict schemas?

**Question.** With weights fixed, do low-precision caches disproportionately damage copying of user-provided identifiers and exact string arguments, and does strict decoding leave those type-valid mistakes intact?

**Gap and contribution.** G9 protects instruction/schema segments already; G6 measures cache-sensitive decisions but does not establish this matched exact-value/full-call contrast. The narrow contribution would be a controlled value-copy diagnostic and deployment guidance for stock GGUF cache settings, not “the first cache study of agents.”

**Minimal experiment.** Original Qwen2.5-1.5B and Llama-3.2-3B weights fixed at FP16. Compare K/V caches FP16, Q8_0, Q4_0 where the pinned official llama.cpp build supports them; keep attention/backend settings identical or report unsupported cells instead of substituting another method. Use free versus whole-response strict decoding, three run seeds, two registered context regimes, and 100 base cases: **2 × 3 × 2 × 3 × 2 × 100 = 7,200 generations**, plus pilot.

Create a separately labelled BFCL-derived diagnostic from suitable literal-string argument cases: replace user-provided opaque identifiers consistently in request and accepted references, without changing tool names/types. Put controlled distractor identifiers in context, balanced by position. Keep these identifiers out of schema enums so the grammar cannot encode the answer. Freeze transformation seeds, exact values, context-token counts, and source IDs. Reuse the official AST checker after consistent reference transformation, and separately report exact-copy error subtypes. This is **derived diagnostic data**, not an untouched BFCL leaderboard score; include an unmodified-case check.

Treat identifier length/position as balanced strata within the fixed diagnostic, not an extra unbudgeted Cartesian sweep. Bootstrap source cases with all cache/context variants together. Measure cache memory, prefill/decode latency, wrong-but-type-valid values, and truncation. Avoid attributing prompt-position or distractor effects to cache precision without the FP16-cache control.

**Cost/time.** Conditional $7.63–$12.74, 6–11 L4 hours plus reserve. Longer contexts increase work despite fewer requests. No custom cache kernels. Selectively preserving schema segments is already overlapping prior art and would introduce an implementation risk unsuitable for this deadline; reserve it for a later project.

**Negative outcome.** Stock Q8/Q4 caches could preserve exact values, all observed losses could come from longer context independent of cache, or strict decoding could remove nearly all failures. A diagnostic-only effect might not transfer to ordinary requests. Report these limits rather than claim general agent unreliability.

## 4. Shared analysis and execution requirements after a choice

For precision p and decoder d, let A(p,d) be official per-item task accuracy. Report signed differences first:

```text
free loss(q)        = A(FP16,free) - A(q,free)
constrained loss(q) = A(FP16,strict) - A(q,strict)
net recovery(q)     = free loss(q) - constrained loss(q)
```

This is an intervention contrast. Full schemas restrict tool names/keys/types and can redirect value choices, so net recovery is not an identified “pure syntactic share.” A ratio to free loss is undefined for a nonpositive loss and unstable when its interval crosses zero. Never force it into a zero-to-one partition.

Use crossed paired resampling of original items and operational runs, retaining every condition/model observation of a sampled item/run. Repeated schedules do not multiply the independent item count. Predeclare the main contrast and how multiple exploratory comparisons are labelled. Report broken→fixed and correct→broken transitions, not only recoveries. For a semantic subanalysis, use overall official accuracy and a fixed baseline-valid cohort; comparing only each arm's own valid subset changes the population.

Grammar compilation failures, context overflow, token-limit exits, parser/conversion failures, and whitespace loops are attempted cases with explicit status, not silent exclusions.
